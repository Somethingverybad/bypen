# Бупень для Windows и Linux

Клиент сети WYX: вход аккаунтом мессенджера, подписанный список узлов,
Xray в процессе, проверка связи и переключение узлов. Исходники находятся
в `desktop/`; iOS, Android и macOS описаны в корневом README.

## Установка

Архивы в `dist/`:

- Windows x64: `bypen-windows-x64.zip`. Распаковать целиком и запустить
  `bypen.exe`; рядом лежат wintun.dll и её лицензия. Окно использует WebView2,
  при недоступности предусмотрен переход в браузер. Видимое окно на сервере
  в ходе проверки не тестировалось.
- Linux x64: `bypen-linux-x64.tar.gz`. Распаковать и выполнить `sh install.sh`
  внутри каталога bypen. Установка для текущего пользователя, без root.
  Интерфейс открывается в Chromium в режиме приложения либо в обычном браузере;
  значок в трее требует совместимой пользовательской графической сессии.
- Контрольные суммы: `cd dist && shasum -a 256 -c SHA256SUMS`.

В режиме прокси приложение меняет пользовательский системный прокси;
его используют приложения, поддерживающие эти настройки. В режиме TUN
помощник запрашивает повышение прав (UAC / pkexec) и меняет маршруты.
На Linux настройка DNS туннеля рассчитана на systemd-resolved/resolvectl;
при их отсутствии текущий код оставляет системный DNS и пишет это в журнал.

## Сборка

Go версии из `go.mod`, zsh, zip, tar и средства загрузки Wintun:

```sh
cd desktop
scripts/build.sh
```

Скрипт собирает Windows/Linux amd64 без cgo, вкладывает Wintun и лицензию,
упаковывает архивы и считает SHA256. Версия — `0.1.<число коммитов>`.
Скрипт пересоздаёт `dist/`; сохранить нужные прежние файлы перед запуском.
Подпись Windows EXE и установщик Windows этим скриптом не создаются.

## Проверки

```sh
go test ./...
go vet ./...
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go test -c -o /tmp/bypen-windows-test.exe .
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go test -c -o /tmp/bypen-linux-test .
```

Полный набор включает локальный запуск ядра и запрос через него с ненастоящим
UUID: отказ удалённого узла ожидаем. Это проверяет запуск SOCKS и конфигурацию,
но не доказывает работу авторизованного VPN-туннеля.

Изоляция проверок: `BYPEN_PORT_BASE=21808`, отдельный XDG_CONFIG_HOME (Linux)
или APPDATA (Windows). Запуск `--headless` поднимает только локальный интерфейс.
`BYPEN_NO_SYSPROXY=1` отключает включение/выключение системного прокси в движке;
для проверок использовать новый каталог конфигурации без старого proxy-состояния.
Не запускать TUN на рабочем VPN-мосте для обычной проверки приложения.

## Передача от Claude к Codex — 18.11.2026

При передаче весь desktop был неотслеживаемой папкой; готовые архивы имели
версию 0.1.17. Исходники были скопированы в /tmp для проверки без изменения
рабочих файлов.

Подтверждено Codex:

- Все четыре существующих теста прошли непосредственно на Windows Server
  и Linux, включая запуск встроенного Xray 26.11.9 на отдельных тестовых портах.
- На macOS прошли проверки конфигураций, подписи и версий, а также go vet.
- Готовые бинарники Windows и Linux запускаются с --headless, отдают HTML
  (HTTP 200), требуют токен для локального API (без него HTTP 403),
  завершаются по /api/quit. На Linux подтверждён код выхода 0.
- Контрольные суммы обоих архивов совпадают с dist/SHA256SUMS.

Пока не подтверждены: вход настоящим аккаунтом, передача пользовательского
трафика через VPN, переключение узлов при сбое, TUN/UAC/pkexec и возврат
маршрутов/DNS после выхода, графическое окно Windows и Linux-трей.
Следующий шаг — проверка этих сценариев на пользовательских Windows/Linux,
после неё решение о распространении. Архивы публично не публиковались.

Новые тестовые копии на серверах помещались в отдельные каталоги с именем
bypen-codex-review; рабочие VPN-процессы и их настройки не менялись.
Секреты и тестовые токены в документ не включать.

## Иконки Windows и macOS — 0.1.18

Windows: assets/icon.ico содержит размеры 16–256 px; rsrc_windows_amd64.syso
встраивает их в EXE для Проводника, панели задач и Alt+Tab. Окно WebView2
использует ресурс 1; та же цветная иконка показана в трее. Меню трея:
открыть, подключить/отключить, выйти. Закрытие окна по-прежнему завершает
приложение. WebView2 обрабатывает и сообщения трея, отдельный цикл не запускается.

После изменения ICO запустить `sh scripts/resources.sh` и сохранить .syso вместе
с исходниками. Генератор закреплён: github.com/akavel/rsrc@v0.10.2.
Переопределение версии сборки: `BYPEN_VERSION=0.1.18 scripts/build.sh`.

Mac: отдельный каталог ios/Mac/Assets.xcassets содержит все размеры AppIcon;
цветной прозрачный пень MenuBarIcon с 1x/2x находится в Mac/Resources и
отображается без template-режима. iOS-иконки не меняются. Воспроизведение:
`swift ios/scripts/gen-desktop-icons.swift <корень bypen>`; затем
`DEVELOPER_DIR=<Xcode>/Contents/Developer BYPEN_VERSION=0.1.18 BYPEN_BUILD=18 sh ios/scripts/build-mac.sh`.
Сборка — универсальная arm64+x86_64, подписывается Developer ID. Нотаризацию
и публикацию скрипт сборки сам не запускает.

Для 0.1.18 проверены загрузка всех девяти размеров из PE-ресурсов непосредственно
на Windows (TestWindowsIconResources), существующие тесты и go vet.
Приложение Mac и помощник собраны универсальными, подписи проверены codesign;
иконки проверяются в итоговом bundle. Реальные меню и панель задач на
пользовательском Windows требуют визуальной проверки после установки.

Mac 0.1.18 одобрен нотариальной проверкой Apple (e2c277e3-2eed-4d22-bee9-baee8ec5a90e).
Билет прикреплён; Gatekeeper принял приложение как Notarized Developer ID,
в том числе после распаковки финального ZIP. Явная подпись helper без
get-task-allow выполняется в scripts/build-mac.sh перед подписью bundle.
Windows Shell успешно извлекает большие/малые значки из окончательного EXE.
Обе версии опубликованы на https://nemilf.hyax.ru/bypen/.
